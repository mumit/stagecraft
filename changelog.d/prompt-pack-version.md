### Added

- **`prompt_pack_version` — a content-hash version for the prompt surface, recorded everywhere, comparable (Phase 33.3).** New `core/prompt-pack.js#computePromptPackVersion`: a sha256 (truncated to 12 hex chars) over every file under `roles/` + `rules/` + `templates/` (stable sorted ordering), so the version changes if and only if a role brief, rule file, or template changes. It's orchestrator-computed, never model-asserted — recorded on the gate two ways, mirroring `dispatched_tool_budget`'s dual-path convention: `core/orchestrator.js#patchGateWithPromptPackVersion` stamps it onto every workstream gate (and the merged stage gate) for headless runs; `core/gates/validator.js#autoInjectMetadata` injects it for user-driven runs. The same value is also recorded on every run-corpus row (`core/corpus.js`, phase-28 item 28.5) and every eval case (`core/evals/capture.js`, phase-33 item 33.1), read straight off the gate.

  New `devteam evals compare --pack <A> --pack <B> [--min-n <n>] [--json]` (`core/evals/compare.js`): per-stage pass-rate deltas between two `prompt_pack_version` values from the run corpus, with dispatch counts, so "did the new principal brief help?" is a query instead of a feeling. Honesty rule: a stage with fewer than `--min-n` dispatches (default 5, the same floor D5 uses in `core/corpus.js#computeStats`) on either pack is reported `refused` and never assigned a delta.

  Docs: `docs/reproducibility.md` new "Prompt-pack version (C4's consumer)" section; `docs/observability.md` corpus record example updated; `docs/reference/cli.md` regenerated.

  Tests: `tests/prompt-pack.test.js` — version changes iff any file's content or path under roles/rules/templates changes, unaffected by files outside those three directories, stable across repeated calls. Propagation, added to the existing suites for each stamping/read site: `tests/orchestrator.test.js` (headless workstream + merged-gate stamping, idempotent — a pre-existing value is never overwritten — and the fire-and-forget contract), `tests/gate-validator.test.js` (the validator's auto-injection for user-driven gates), `tests/corpus.test.js` (a corpus row via `recordDispatch`, `null` when the gate has none), `tests/evals-capture.test.js` (a captured eval case). `tests/evals-compare.test.js` — per-stage deltas on a fixture corpus, the minimum-n refusal (default and custom `--min-n`), stages that only appear for one pack, an empty corpus, and the CLI's `--pack`/`--json` wiring including the "exactly two `--pack` values" guard.

  Honest scope note: `prompt_pack_version` hashes this framework installation's own bundled `roles/`/`rules/`/`templates/` directories, not a target project's installed `.devteam/{rules,templates}/` copy — those can diverge if a project hand-edits its installed rules (`core/adapters/base-install.js`'s `installRules`/`installTemplates` skip existing files by default), and role briefs are rendered into per-host formats with no single installed `roles/` directory to hash consistently across hosts (see `base-install.js`'s header comment). The version therefore answers "did the framework's own prompt surface change" reliably; it does not detect a project's local customization drifting from what it was installed with.
