### Added

- **Compact-QA fold on `quick` — phase-29 item 29.4.** Tracks flagged `compact_qa` (currently just `quick`) now dispatch a single combined `verification-sweep` stage (`stage-06x`) instead of one dispatch per specialty-QA stage they include. On `quick` this folds `accessibility-audit` (06b) and `performance-budget` (06e) — the two of the four specialty-QA stages (`accessibility-audit`/06b, `observability-gate`/06c, `verification-beyond-tests`/06d, `performance-budget`/06e) `quick` actually lists — into one dispatch, same PASS/FAIL bar per section, one gate instead of two. `full` and `hotfix` are untouched: they aren't flagged `compact_qa`, so they keep dispatching all applicable specialty-QA stages standalone. Implementation: `core/pipeline/stages.js` gains a new `"verification-sweep"` stage definition, `isCompactQaTrack()`/`foldQaSweep()`, and applies the fold inside `orderedStageNamesForTrack()` — the single call site every consumer (driver dispatch, `verifyChain` predecessor derivation, right-sizing, `devteam assess`/ceremony-preview) already goes through, so `devteam next`/`merge`/`summary` handle `stage-06x` like any other stage with no further changes. `STAGES_BY_TRACK` itself is untouched — it stays the declarative "which specialty QA does this track need" answer; folding is a presentation-layer transform. New schema `core/gates/schemas/stage-06x.schema.json` embeds the four existing stage-06[b|c|d|e] shapes as optional, individually-`$ref`'d sections behind a `sections_included[]` discriminator — a document with any subset of the four populated (the folded form) validates, and the four original schemas are unchanged (the unfolded form full/hotfix still produce). Right-sizing (`core/pipeline/right-sizing.js`) skips the folded slot only when none of the four constituent triggers fire, mirroring how each standalone stage was skipped independently before.
  Tests: `tests/compact-qa-fold.test.js` (fold mechanics; full-track stage definitions + rendered prompts are byte-identical to their pre-29.4 shape; stage-06x schema accepts both the folded and unfolded gate shapes; right-sizing skip logic for the combined slot); `tests/pipeline-e2e.test.js` (new `quick` track e2e: exactly one `verification-sweep` dispatch where it previously made two, single `stage-06x.json` gate on disk carrying both sections); `tests/performance-budget.test.js` and `tests/run.test.js` updated — both encoded `quick`'s pre-fold track shape (performance-budget dispatching standalone, a 2-item right-sizing skip list) and needed to reflect the fold.
  Honest scope note: the plan item's acceptance text ("quick-track stubbed run makes 1 dispatch where it made 4") describes the aspirational four-section fold; `STAGES_BY_TRACK.quick` has only ever listed two of the four specialty-QA stages (`accessibility-audit`, `performance-budget` — not `observability-gate` or `verification-beyond-tests`), so the actual, verified change is 2 dispatches folded into 1. The fold mechanism (`foldQaSweep`) is generic over however many of the four a `compact_qa` track lists, so a future track that includes all four would get the full 4-in-1 fold with no further code change. Auto-remediation (`core/a11y-fixer.js`), the per-stage fix-recipe registry (`core/pipeline/fix-recipes.js`), and the dashboard's stage-specific renderers (`core/report/`, `core/ui/static/app.js`) still key off the standalone `stage-06b`/`stage-06c`/`stage-06d`/`stage-06e` gate files and are not wired to the folded `stage-06x` shape — out of scope for this item (see the final report's Out-of-scope findings).
