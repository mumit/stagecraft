### Added

- **`devteam run` assesses inline when no track is decided — phase-29 item 29.2 (ADR-016, supersedes [ADR-006](../docs/adr/006-track-inference-under-autonomy.md) §1).** When `devteam run` starts with no `--track`, no `pipeline/track.json`, and no `pipeline.custom_stages`, and there is a `--feature`/description to assess, `core/driver.js`'s `resolveTrack` now calls the same `assess()` heuristic `devteam assess` uses (`core/stage-shopping/assess.js`) — at *any* confidence level, not just the "high"-only downgrade the pre-existing `right-sizing.md` behavior shipped — and returns the result with `source: "inferred"`. `run()` persists that decision to `pipeline/track.json` itself (`assessed_by: "devteam run <version> (assess-inline, ADR-016)"`), so the file `devteam assess` would have produced exists regardless of whether an operator ran it first; the unchanged `checkTrackConfidence` guard (ADR-006 §3/4) still warns or halts on medium/low confidence exactly as it does for a hand-run `devteam assess`. `--track` always wins and records `source: "human"`; an existing `pipeline/track.json` is never re-assessed or overwritten. `core/cli/commands/run.js` prints the recommendation, its reasons, and — until [29.3](../plans/phase-29-scale-adaptive-ceremony.md) lands the token/cost ceremony estimate — the stage-slot/dispatch counts already computed for the run plan, with a `TODO` citing 29.3. No interactive prompt anywhere; behavior is identical in CI and interactive use. Docs: `docs/tracks.md`, `docs/adr/016-assess-by-default.md` (new), `docs/adr/006-track-inference-under-autonomy.md` (addendum), `docs/adr/README.md`. Tests: `tests/run.test.js` — inline-assess writes `pipeline/track.json` and resolves the expected track/confidence; `--track` overrides and writes no file; a pre-existing `pipeline/track.json` is untouched byte-for-byte; a CLI-level "snapshot" test of the printed recommendation/rationale/ceremony-count/TODO block and the resulting `pipeline/track.json` contents. Honest scope note: `assess()` cannot recommend the `loop` track (phase-29 item 29.1) — its heuristic only returns `hotfix | dep-update | config-only | nano | quick | full`, so a `loop`-shaped change (e.g. a one-paragraph feature) will still be inferred as `quick` or `full` rather than `loop`; teaching `assess()` about `loop` is out of scope for this item. Also out of scope: the ceremony *cost* estimate (token/dollar range) that 29.3 is meant to add in place of today's slot/dispatch-count placeholder, and rendering the recommendation in `--watch` mode (the watch renderer has its own compact format and does not currently surface `assess_inline`).
