### Added

- **Agent Client Protocol (ACP) host adapter — phase-34 item 34.1 (`docs/user-guide.md` "Using ACP", `core/adapters/host-adapter.md`).** `hosts/acp/` speaks [Agent Client Protocol](https://agentclientprotocol.com) (Zed, JetBrains, Google, GitHub, 25+ agents) as a *client* over stdio, so any ACP-compatible coding agent becomes a Stagecraft host with zero adapter code written per agent — verified against the published schema (`zed-industries/agent-client-protocol` `schema/v1/schema.json`, protocol version 1, pinned in `hosts/acp/capabilities.json`'s `acpProtocolVersion`) rather than prose docs alone, since the docs site omits transport framing (newline-delimited JSON-RPC 2.0 over stdio; stdout carries only protocol messages, stderr is agent logging). `hosts/acp/jsonrpc.js` is a from-scratch ~130-line bidirectional JSON-RPC client (no new npm dependency — same house style as the existing `claude-stream-json`/`codex-exec-json` line-JSON extractors) since ACP requires both directions: Stagecraft sends `initialize`/`session/new`/`session/prompt`, and the agent sends `session/request_permission` back plus `session/update` progress notifications. Dispatch = initialize → session/new → one `session/prompt` turn with the rendered stage prompt → stream `session/update` into `pipeline/logs/<workstreamId>.log` → best-effort `session/close` → resolve once the turn ends (`stopReason`) and the gate file is checked (the existing hooks:false poll fallback in `core/orchestrator.js` covers the rest).
  - **Enforcement mapping (`hosts/acp/permissions.js`).** Every ACP tool call is a `session/request_permission` round-trip *before* it executes, carrying `kind`/`locations`/`rawInput` — real structure to decide on, unlike claude-code's own tool-call-time enforcement (static per-project permission globs configured once at install, `hosts/claude-code/adapter.js` `renderSettingsLocal`). The adapter checks the *live* per-dispatch `descriptor.allowedWrites` (via `core/guards/write-audit.js`'s `isAllowed`) for edit/delete/move tool calls, and a claude-code-parity dangerous-command stoplist (`rm -rf`, `git push --force`/`-f` — mirroring `renderSettingsLocal`'s `permissions.deny`, not `core/guards/stoplist.js`'s topic-based auth/crypto/PII patterns, which gate track selection for a whole run and would false-positive on ordinary full-track work touching e.g. `auth.js`) against the tool call's title/rawInput. `capabilities.json` declares `allowed_writes`/`stoplist: "tool-call-time"` — **the first non-claude-code host with call-time enforcement**, closing part of the enforcement-parity gap the landscape review flagged. Deny/allow always selects a real offered `PermissionOption` (`reject_once`/`allow_once` preferred over the `_always` variants, since Stagecraft re-decides every call from the current descriptor); silence never defaults to permissive — an unmatched deny cancels the turn rather than falling through to allow.
  - **Routing (`core/config.js`, `core/router.js`, `core/orchestrator.js`).** `routing.roles.<role>`/`routing.stages.<stage>` gain a third string shape, `"acp:<agent-command>"` — there's no single default ACP binary the way there is for claude/codex/gemini, so the launch command travels with the route itself. `normalizeRouteValue` parses it into `{host: "acp", agentCommand}`; the object form (`{host: "acp", agentCommand: "..."}`) works too. `resolveRoute`/`resolveAdapter` surface `agentCommand` alongside `hostName`/`model` (same "rides on the descriptor" pattern 32.3 established for `model`) — added *only* when non-empty, so every pre-34.1 route shape stays byte-identical (verified by re-running the existing `deepEqual`-based back-compat tests unchanged). `hosts/acp/adapter.js`'s `resolveAgentCommand` resolution order: `DEVTEAM_HEADLESS_COMMAND` → `descriptor.agentCommand` → `.devteam/config.yml` `hosts.acp.command` → `capabilities.headlessCommand` (a runnable reference default, `npx -y @agentclientprotocol/claude-agent-acp` — the official ACP bridge for Claude Code; any other agent needs an explicit command).
  - **Wording fix (`core/adapters/render-helpers.js`).** `allowedWritesCaption`'s tool-call-time wording hardcoded "hooks" — accurate for claude-code but wrong for ACP, which enforces via permission requests, not hooks. Added an optional `mechanism` parameter (default `"hooks"`, byte-identical for every existing caller) that `core/adapters/markdown-host.js` now threads from a new optional `capabilities.enforcementMechanismLabel` field; `hosts/acp/capabilities.json` sets it to `"permission requests"`.
  - Tests: `tests/host-acp.test.js` (end-to-end stage completion via a scripted stub agent, an out-of-allowedWrites edit denied at call time via a real `reject_once` option, the `rm -rf` stoplist denied the same way, a malformed non-JSON protocol line terminating the session with a reported `protocolError` instead of hanging, an agent that never responds bounded by `ctx.timeoutMs`, plus unit coverage of `permissions.js`), `tests/fixtures/acp-stub-agent.js` (the scripted agent — speaks the wire protocol directly, independent of `hosts/acp/jsonrpc.js`, so a framing bug there can't hide behind a shared implementation), `tests/config.test.js` and `tests/router.test.js` (the `acp:<command>` routing form + back-compat), `tests/adapter-contract.test.js` (added to `PROMPT_ONLY_HOSTS`, `HOSTS_WITH_RENDER`, `SHARING_HOSTS`, and the 6.1 tool-budget-resolution host list — the shared gate-footer equivalence check passes unmodified, confirming the enforcement-level wording fix above didn't leak into the footer boundary).
  - Honest scope note: `telemetry: "estimated"` — ACP has no standardized usage/cost field, so this adapter falls back to the same promptBytes/4 estimate every non-native host uses. `subagents`/`hooks`/`goalLoop`/`worktrees` are all `false` — Stagecraft doesn't wire into any ACP-side equivalents here. Enforcement only covers tool calls the agent honestly reports via `kind`/`locations`/`rawInput`; an `execute`-kind tool call that writes files via shell redirection isn't checked against `allowedWrites` (same gap claude-code's own Bash permission model has — Bash isn't glob-restricted to allowed directories either, only the dangerous-command deny-list applies). No post-hoc write-audit backstop is layered on top, matching the precedent every other `"tool-call-time"`-declaring host (claude-code) already sets. ACP server mode (Stagecraft driven *by* another tool) is explicitly out of scope, per the phase-34 plan.
