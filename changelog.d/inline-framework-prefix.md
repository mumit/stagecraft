### Added

- **Inline the framework set and role brief into the cacheable prompt prefix (phase-37 item 37.2).** Layers 1-2 of every stage prompt — `AGENTS.md`, `.devteam/rules/pipeline.md`, `.devteam/rules/gates-core.md`, and the role brief — now carry those files' actual content, in the stable order phase 32.1 established, instead of just naming their paths. The verify-first measurement in `plans/phase-37-interface-and-token-efficiency.md` §37.2 found the pointer-only prefix shared across two same-role dispatches was 213 B (12.7% of the prompt; the plan's own prior measurement cited 268 B/15.2%) — the ~22 KB framework block was paid at full price every dispatch via 4+ sequential tool-call reads, with almost nothing cacheable. Inlining moved the shared prefix to 18,932 B (92.8%) in the same measurement, and eliminates those reads entirely. New config `prompts.inline_framework` (default `true`) gates this; `false` reproduces the pre-37.2 path-pointer rendering byte-for-byte, for a host with no prefix caching and a small context window. `openai-compat`'s existing `cache_control` breakpoints (32.1) land after the now much larger inlined block unchanged. `core/evals/run.js`'s structural scoring now recognizes both the inlined and pointer framework headings.

  Honest scope note: `docs/reference/prompt-budget.md`'s per-dispatch byte totals are unchanged by this item — that doc already counted the full framework + role-brief bytes as consumed per dispatch regardless of whether they arrived inline or via a tool-call read, so there is nothing to re-baseline there; the growth this item causes is in the *literal* rendered-prompt size (measured above), not in that file's metric, and `npm run consistency`'s prompt-budget advisory does not fire. Rewriting the role briefs to be smaller (tempting now that their size is cacheable) is explicitly out of scope for this phase.
