### Changed

- **`devteam --help` collapses from 343 lines to one screen, grouped by what you're trying to do — Phase 37.4.** The default listing doubled as the full flag reference, which meant a new user's first screen was 343 lines long. `core/cli/commands/help.js` now defaults to a ~27-line grouped view (`Start here`, `Daily`, `Review`, `Verify`, `Fix & retry`, `Learn`, `Audit`, `Setup & tools` — one line per group, commands separated by `·`) built from every entry in `core/cli/command-list.js`. The full listing — same content, nothing lost — moves behind `devteam --help --all` / `devteam help --all`, and still backs the generated `docs/reference/cli.md` (unchanged apart from documenting the new `--all` flag itself). `bin/devteam`'s `-h`/`--help`/no-argument branch now runs the shared flag parser against `help`'s own flag schema instead of ignoring everything after the flag, so `--all` reaches `help.run()`. Unknown-command messages (`devteam help <typo>`, `devteam <typo>`) now show the grouped view instead of the full one, for the same one-screen reason.

  No command renames or removals — presentation only. Grouping decisions belong in one place: `GROUPS` in `help.js`, exported for tests.

  Tests: `tests/help-cmd.test.js` gained — default help ≤ 45 lines; `help --all` and `--help --all` both print the full reference (`Commands:`/`Quickstart:`); a coverage test that every command in `command-list.js` appears in `GROUPS` exactly once, so a future command can't be added without being grouped; unknown-command fallback shows the grouped view. Updated three pre-existing tests that encoded the old "default help is the full listing" behavior: `help-cmd.test.js`'s no-argument and unknown-command assertions now check for the grouped view (their old assertions moved to the new `--all` test); `cli.test.js`'s per-command coverage regex loosened from start-of-line matching (which assumed one command per line) to a word-boundary match, since commands now share a line within a group; `evidence-status.test.js`'s help-listing assertion split into a default-help check (`evidence` — the bare command name) and an `--all` check (`evidence status` — the subcommand detail that moved).

  Honest scope note: `docs/reference/cli.md` is *not* byte-unchanged as the plan item's acceptance criterion literally states — adding the `--all` flag itself to `help`'s schema (needed so `parseFlags` accepts it and `generateHelp`/`docs:generate` stay the single source of truth for flag docs) adds one documented flag row to the generated reference's `help` section. The alternative — special-casing `--all` outside the flag schema — would have made `devteam help --all` and `devteam --help --all` diverge in how they parse the flag, which seemed worse than a four-line doc diff.
