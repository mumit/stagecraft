### Added

- **`devteam patterns export --skill` — SKILL.md export of promoted patterns, phase-30 item 30.5 (`docs/pattern-learning.md`).** Serializes every currently-promoted pattern (`prompt_text`, `tier`, `domain`, and a short evidence-based rationale — never raw observations) into a `SKILL.md` file following the [Agent Skills open standard](https://agentskills.io/specification) (spec fetched 2026-07-31: `name` 1-64 chars, lowercase alnum/hyphen, no leading/trailing/consecutive hyphen, and must match the parent directory name; `description` 1-1024 chars), so the same learned knowledge loads natively in Claude Code, Codex, Cursor, and Gemini/Antigravity outside a devteam run. Because `name` must match its directory, `[--out <dir>]` is treated as a *parent* directory rather than the skill directory itself — the skill always lands at `<out>/learned-patterns/SKILL.md` (`.devteam/learned-patterns/SKILL.md` by default) — so the constraint holds unconditionally instead of only for the default path. The generated file opens with `<!-- Generated by devteam patterns export; regenerate to update; do not hand-edit. -->` and groups patterns into one Markdown section per `domain`; re-exporting with an unchanged `promoted.json` produces a byte-identical file (no timestamps embedded). The rendered output is re-scanned with the same secret-scan path `devteam patterns promote` already uses (`core/hooks/secret-scan.js`'s `scanContent`) before anything is written — defense in depth against a hand-edited `promoted.json`, since `prompt_text` is otherwise only scanned once, at promotion time. `devteam init` now mentions the export path in its summary output — never auto-installs it — whenever promoted patterns already exist and at least one host being initialized declares a `skillsDir` in its adapter capabilities (read per-adapter, not hardcoded, so a new host adapter picks this up automatically). Docs: `docs/pattern-learning.md` (new "SKILL.md export (30.5)" subsection under Privacy and Export, plus a history update), `docs/reference/cli.md` (regenerated). Tests: `tests/patterns.test.js` — export produces spec-conformant frontmatter (name/description constraints, name-matches-directory-name) and a domain-grouped body; two exports over an unchanged `promoted.json` are byte-identical; `--out` always resolves to `<out>/learned-patterns/`; a `promoted.json` hand-edited to contain a secret-shaped `prompt_text` is rejected and no file is written; the CLI subcommand round-trips end-to-end and errors with exit code 2 when `--skill` is omitted. `tests/init.test.js` — the export tip appears only when promoted patterns exist *and* the initialized host has a skills directory, confirmed both ways plus for `generic` (no `skillsDir`) with patterns present. Honest scope note: only the Agent Skills format is supported (`--skill` is currently mandatory, not a choice among formats); `devteam init` never copies the exported directory into a host's skills directory itself — that copy step stays manual, consistent with the item's "no auto-install without the existing init overwrite rules."
