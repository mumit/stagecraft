### Added

- **Wire the pattern-learning outcome-feedback counters and add a demotion flow — phase-30 item 30.2 (`docs/pattern-learning.md`).** `stats.injected` and `stats.recurrence_after_injection` on a promoted pattern were initialized at promotion and never incremented anywhere; this closes that loop. `core/patterns.js` gains `recordInjection()`, called at real DISPATCH time only — `core/orchestrator.js`'s `runStageHeadless` (both the normal per-workstream path and the omnigent-director path) and `core/cli/commands/stage.js`'s non-headless "print the prompt for a human to paste into a host" path — never at a preview/render-only call to `runStage()` (`devteam reproduce`, `devteam replay --dry-run`), since no model ever sees those renderings. Each real dispatch increments every injected pattern's `stats.injected` once and appends a `pattern-injected` run-log event. `collect()` reads those events back and increments `recurrence_after_injection` when a blocker maps to a pattern id that was injected into that same stage's dispatch this run; detection is keyed by gate file identity (a new `.devteam/patterns/recurrence-checked.json`), not observation fingerprint, because a recurring blocker shares its fingerprint with the observation that got the pattern promoted in the first place. `devteam patterns review` now flags a promoted pattern as a demotion candidate once `recurrence_after_injection` reaches `patterns.demotion_recurrence_threshold` in `.devteam/config.yml` (default `3`) — flagging only, never automatic. `devteam patterns demote <id>` is the new explicit operator action that moves a promoted pattern back to candidate status into `.devteam/patterns/demoted.json`, recording an audit line (`demoted_by`, `demoted_at`, `reason`, `counters_at_demotion`) that survives a later `devteam patterns promote <id>` re-promotion. Docs: `docs/pattern-learning.md` (new "Outcome-Feedback Counters" section, updated Storage/Open Decisions), `docs/reference/cli.md` (regenerated). Tests: `tests/patterns.test.js` — a real headless dispatch increments `stats.injected` exactly once while a preview-only `runStage()` call never does; a seeded three-attempt recurrence scenario flags the pattern in `devteam patterns review` and stays idempotent on a second `collect()`; demote → promote round-trips preserve `demotion_history` and re-enable selection; counters persist across `collect()`/`promote()` cycles without one pattern's write clobbering a sibling's stats. Honest scope note: `stats.noise_reports` remains unwired — no command produces a noise report yet, so review can only ever flag on recurrence, not operator-reported noise. Auto-demotion and auto-retirement remain explicitly out of scope, consistent with the design doc's "promotion is explicit" stance.
