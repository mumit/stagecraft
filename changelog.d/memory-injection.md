### Added

- **Memory retrieval into stage prompts + auto-ingest at run end — phase-30 item 30.4 (`docs/memory.md`).** When `.devteam/memory/` already exists and `memory.inject` isn't `false` (both true by default once a project has run `devteam memory ingest` at least once), every **headless** stage dispatch (`devteam run`, `devteam stage --headless`) now queries the store for the top `memory.inject_top_k` (default 3) chunks similar to the stage's feature/brief text, filters by `memory.inject_similarity_floor` (default `0`), and renders a bounded (≤1,200 bytes) `## Prior Project Knowledge` section with kind + source attribution per entry — same greedy accumulate-skip-oversized budget discipline as `Known Project Patterns` (`core/patterns.js` `selectForDescriptor()`). Stage 2 (design) descriptors additionally query the org-shared store for `kind: adr`, making `devteam architecture lookup` automatic instead of a role-brief-only suggestion (`roles/principal.md` updated; the manual command remains for deeper/broader queries). `core/driver.js` also auto-ingests once at a clean `pipeline-complete`, gated on the same `.devteam/memory/`-exists condition and reusing `memory.inject` as the single on/off switch for both sides of the loop — fire-and-forget, an ingest failure (including the optional `@huggingface/transformers` dependency being absent) is logged (`memory-ingest-failed`) and never fails the run. New config: `memory.inject` (default `true`), `memory.inject_top_k` (default `3`), `memory.inject_similarity_floor` (default `0`). New module `core/memory/inject.js` (`priorKnowledgeForStage()`) and `renderPriorKnowledge()` (`core/adapters/render-helpers.js`, wired into all seven host adapters). *Honest scope note:* `buildDescriptor()`/`runStage()` (`core/orchestrator.js`) are and remain synchronous — 37 direct `runStage()` calls and 25+ `buildDescriptor()` calls across the test suite, plus three preview-only CLI commands (`devteam stage` without `--headless`, `devteam reproduce`, `devteam replay`), assume a plain synchronous return, and embedding is inherently async. Retrieval is therefore pre-fetched in `runStageHeadless()` (the one dispatch path that was already async) and threaded through as a plain `opts.priorKnowledge`/`descriptor.priorKnowledge` field; the interactive (non-headless) preview path does not query memory. Tests: `tests/memory-injection.test.js` — gating (blank query text, no store, `memory.inject: false`), similarity-floor filtering + kind/source attribution, deterministic budget truncation favoring highest similarity, stage-02-only org query, one-warning embedder-absent degradation, `renderPriorKnowledge()` rendering, `buildDescriptor()`/`runStage()` threading (byte-identical prompts when absent), an end-to-end `runStageHeadless()` wiring test with a hand-seeded store record (deterministic similarity via an identical query/stored embedding), a stage-02 org-ADR end-to-end test, and driver auto-ingest (store-present/absent, `memory.inject: false`, and the fire-and-forget failure contract). `tests/config.test.js` covers the new config defaults/overrides. No pre-existing tests required changes: gating auto-ingest on `.devteam/memory/` already existing means the many driver tests built on `makeTargetProject()`'s bare fixture (no memory store) see zero new run-log events.
