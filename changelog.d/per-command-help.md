### Fixed

- **`devteam help <command>` and `devteam <command> --help` now print real, command-scoped help — Phase 37.1.** Previously `devteam help <anything>` ignored its argument and printed the identical 343-line full command list regardless of what was passed. Both forms now generate help from that command's own flag spec (`core/cli/flags.js#generateHelp`) — a synopsis/usage line, then each flag with its `(type)` and description — with no hand-written per-command prose to drift out of sync. `devteam help <command>` delegates to the target command's own `--help` handling (`cmd.run([], { help: true })`), so the two forms are guaranteed byte-identical: it's the same code path, not two implementations kept in sync by hand. `devteam help` with no argument is unchanged. An unknown command name (either form) now prints the full command list plus a "did you mean" suggestion from a small Levenshtein-distance helper (`core/cli/nearest-match.js`, no new dependency). The `bin/devteam` → command-module map moved to `core/cli/command-list.js` so `help.js` and `bin/devteam` resolve command names from one shared list instead of two.

  Also fixed: `devteam hosts --help` and `devteam stages --help` previously exited 2 ("Unknown flag: --help") since neither command declared a `help` flag; both now support it like every other command.

  Tests: `tests/help-cmd.test.js` — `help run` and `run --help` produce byte-identical output under 60 lines covering all 21 of `run`'s flags with their types; output differs between two different commands (the regression this item fixes); an unknown command name suggests a near match via both entry points; `help` with no argument is unchanged; and a meta-test asserting every flag in every one of the 44 command modules has a non-empty description (all already did — no spec fixes were needed). `tests/flags.test.js` gained a unit test for `generateHelp`'s new `(type)` tag.

  Honest scope note: the "synopsis line" called for in the plan item is realized as the existing generated `Usage: devteam <command> [options]` line rather than a new hand-authored one-line blurb per command — adding a separate synopsis field to all 44 modules would have created a second place (beyond the flag spec) to keep in sync, working against the single-source-of-truth goal this item is for.
