### Added

- **Opt-in Reflector pass — phase-30 item 30.3 (`docs/pattern-learning.md`).** `learning.reflector: true` in `.devteam/config.yml` (default `false`) makes the driver dispatch one extra headless call after a *clean* `pipeline-complete` — never on a halt — routed like any role (`routing.roles.reflector`, falling back to `routing.default_host`) so it can go to a cheaper model than the build agents. `core/learning/reflector.js` builds the dispatch prompt from the new `roles/reflector.md` brief plus embedded JSON (this run's gate summaries, `run-log.jsonl` events with heartbeats stripped, and the current promoted-pattern set — the model gets no live tool access to re-read them) and spawns the resolved host's headless command directly (same one-off-dispatch shape as `core/a11y-fixer.js`, not a stage dispatch — there is no gate footer telling the model to write a gate, because this isn't one). Output must be a single JSON object matching the new `candidates-delta` schema (`core/gates/schemas/learning/candidates-delta.schema.json`, deliberately filed under a `learning/` subdirectory so it isn't picked up by the stage↔schema 1:1 sweeps in `contract.test.js`/`scripts/consistency.js`), hand-validated by `core/learning/validate-candidates-delta.js` (no ajv dependency, matching this repo's existing `core/gates/validator.js` convention). Valid `new_candidates` — including the new `tier: "positive"`, which gate-derived collection structurally cannot produce — land in the same observations store via the new `patterns.ingestReflectorCandidates()`, tagged `source: "reflector"` and fingerprint-deduped exactly like gate-derived observations, so a reflector proposal can reinforce an existing candidate's `pattern_key` instead of always minting a new one. `counter_adjustments`/`dedup_merges` are advisory-only — logged in full as a `reflector-proposal` run-log event for an operator to act on through the existing `devteam patterns demote`/`promote` flow, never auto-applied. Malformed output (invalid JSON, or JSON failing schema validation) is discarded *in full* — one `reflector-output-malformed` event, nothing partially ingested. Any dispatch failure (no adapter, no `headlessCommand`, non-zero exit, timeout) is the same fire-and-forget contract as pattern auto-collection: one `reflector-dispatch-failed` event, never fails the run. Role brief registered in `core/roles.js` (`ROLE_TOOLS.reflector`, read-only: `Read, Glob, Grep`) and `hosts/claude-code/adapter.js` (`ROLE_FRONTMATTER.reflector`, `model: haiku`). Docs: `docs/pattern-learning.md` (new "Reflector (ACE-lite)" section, citing Zhang et al. arXiv:2510.04618, plus an Open Decisions/history update). Tests: `tests/reflector.test.js` — `validateCandidatesDelta` unit coverage; an end-to-end scripted-headless-output run lands a `source: "reflector"` candidate and logs the proposal event; invalid-JSON and schema-invalid outputs are each discarded whole with exactly one malformed-output event and zero observations written; disabled-by-default runs never invoke the reflector and emit no `reflector-*` events; a throwing `runReflector` is caught and logged without failing the run (fire-and-forget contract); `roles/reflector.md` stays under a single-page byte budget. Honest scope note: `counter_adjustments` and `dedup_merges` are recorded for audit but have no dedicated review-surface UI yet (no CLI command reads them back out) — they're visible today only via `run-log.jsonl`; auto-promotion remains explicitly out of scope, per the design doc's "the Curator is the existing human promote flow."
