### Added

- **Per-role orchestrator stamping for stage-04 (Build) — Phase 31.1.** Orchestrator-stamped verification previously stopped at `plan.workstreams.length === 1`, so build's four role workstreams (backend/frontend/platform/qa) and their merged gate were never independently verified — only model self-report. Two new stamp scopes in `core/verify/stamp.js`: `stampStage04Workstream` runs a lint check scoped to each role's `allowedWrites` directories (paths appended as extra args to the configured lint command — best-effort; tools that ignore extra positional args just lint the whole project, but `scoped_paths` records what was requested) and stamps `lint_passed`/`tests_passed` onto that role's own gate as it completes (wired into `core/orchestrator.js`'s per-workstream dispatch loop); `stampStage04Merged` runs the full test suite exactly once, after `mergeWorkstreamGates` writes the merged `stage-04.json` (wired into `core/driver.js`'s merge handler), and overrides a model-claimed `tests_passed` that disagrees with the observed suite result. `mergeWorkstreamGates` now rolls any per-role `tests_passed` self-report into the merged gate so the merged-level check has a claim to compare against. Verification receipts (already content-addressed by command+workspace+config+env) mean the per-role test checks and the merged check collapse to one real subprocess execution rather than one per workstream — proven via receipt-hit counting, not new dedup logic. Tests: `tests/verify-stamp.test.js` (lint scoping, status-flip + model_said audit trail, skip messaging, merged override, receipt-collapse across 4 roles + merge, dispatch rejection paths), `tests/orchestrator.test.js` (`tests_passed` roll-up aggregation, end-to-end `runStageHeadless` wiring including `stamp: false`), `tests/run.test.js` (driver wires the merged stamp in after merge and it wins over the model's claim). Existing single-workstream stamping (stage-03b/04a/06) is untouched — same code path, same behavior.

  Honest scope note: lint scoping is best-effort (path args aren't guaranteed to be honored by every lint tool/config); the standalone `devteam merge` CLI command does not yet trigger the merged-level stamp (only the `devteam run` driver loop does); `devteam verify stage-04` does not yet support on-demand multi-workstream re-stamping. All are natural follow-ups, not required for this item's acceptance criteria.
