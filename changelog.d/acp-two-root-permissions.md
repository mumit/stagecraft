### Added

- **Two-root permission model for the ACP host — phase-36 item 36.1 (`plans/phase-36-external-review-mode.md`).** `hosts/acp/permissions.js#evaluateToolCall` accepted a single `cwd`; it now also accepts `{ codeRoot, stateRoot, mode }`, the mechanical primitive a future external-review entry point needs to make "read-only review" an enforced guarantee rather than a prompt instruction. A bare cwd string still works exactly as before (`mode: "normal"`, one root doing double duty as both — byte-identical, no existing permission test was touched) — `hosts/acp/adapter.js`'s `invoke()` now builds this roots object every call (`codeRoot: processCwd, stateRoot: ctx.cwd, mode: ctx.externalReviewMode ? "review" : "normal"`), migrating the one production call site in the same commit rather than leaving two code paths.

  In `mode: "review"`: any `edit`/`delete`/`move` resolving inside `codeRoot` is denied outright — read-only, regardless of `allowedWrites` — with a reason naming read-only mode; writes under `stateRoot` are still checked against `allowedWrites` relativised to `stateRoot`; paths outside both roots stay denied, as today.

  **Closed the `execute` gap**, the substantive half of this item: `WRITE_KINDS` (`edit`/`delete`/`move`) never covered `kind: "execute"`, so a shell call (`sed -i`, `git checkout`, a build script) could mutate the subject under review with no check at all — while review genuinely needs shell for `rg`/`grep`/`git log`. In review mode, `execute` is now deny-by-default with a read-only allowlist (`rg`, `grep`, `git log`/`diff`/`show`/`status`, `ls`, `cat`, `find`, `wc`, extendable via `hosts.acp.review.exec_allowlist` in `.devteam/config.yml`), parsed to argv via the existing `core/command-line.js#parseCommandLine` — never substring-matched — with any redirection or shell metacharacter (`> >> | ; & $( \``) denied outright before the binary name is even looked at, since those decide what a *real* shell (the reviewing agent's own) would do with the command, not this evaluator. Deny reasons quote the offending command. `normal` mode's `execute` handling is unchanged — only the pre-existing dangerous-command stoplist applies.

  Tests (`tests/host-acp.test.js`): a same-descriptor, same-toolCall write into `codeRoot` denied in review mode / allowed in normal mode; a `stateRoot` write matching `allowedWrites` allowed, one not matching denied; a write outside both roots denied; `codeRoot` absent (36.5's diff-only review shape) falls through to the `stateRoot` check without crashing; `rg foo` allowed and `sed -i ...` denied in review mode while `sed -i ...` stays allowed (unrestricted) in normal mode; `rg foo > out.txt` denied (redirection), plus pipes/backgrounding/`$()`/backticks/semicolons denied even behind an allowlisted leading binary; `git` restricted to `log`/`diff`/`show`/`status` in review mode; the `exec_allowlist` config extension point adds to, not replaces, the defaults; a no-command `execute` call denies by default; `read`-kind calls stay ungated by location in review mode, matching normal mode (deliberately unclosed — see `plans/acp-read-scope.md`'s 36.0 caution note, needed for 36.2's absolute-framework-path mechanism); and one adapter-level wiring test (`adapter.invoke` with `ctx.externalReviewMode: true`) proving the same write is allowed with the flag off and denied with it on, not just the unit-level function. All 14 pre-existing `hosts/acp` permission/adapter tests pass completely untouched.

  Honest scope note: `ctx.externalReviewMode` is read by `hosts/acp/adapter.js` but set by no orchestrator path yet — 36.3/36.4 (review workspace + `devteam review`) are what will flip it on for real. The redirection/metacharacter check is deliberately conservative: it denies a character match anywhere in the raw command string, including inside quotes (e.g. `rg "a>b"` is denied), because this evaluator only ever grants *permission* — the command still runs in the reviewing agent's own shell, and a quote-aware parse here would have to correctly model that shell's quoting rules to stay safe. If that turns out to make real reviews impractical, the fix is the `exec_allowlist` extension point or a narrower parse, not silently loosening the default. As already flagged in `plans/phase-36-external-review-mode.md`'s 36.0 note, `read`-kind calls carry no location check in review mode either, by design — 36.2 depends on a review/build agent being able to read outside `codeRoot` — so this item does not make review mode read-only for `read`; it makes it mechanically write-and-execute-safe.
