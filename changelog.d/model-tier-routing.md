### Added

- **Per-role/per-stage model-tier routing + escalate-on-retry — phase-32 item 32.3 (`docs/user-guide.md` "Pinning a model in routing config", `docs/cost.md`).** `routing.roles.<role>` and `routing.stages.<stage>` now accept either the pre-32.3 bare host-name string (unchanged, still the only form `devteam init` writes) or `{host, model}` to also pin a model for that role/stage. `core/config.js`'s new `resolveRoute(config, stage, role)` implements the unchanged stage→role→critic-diversity→default_host precedence but returns `{hostName, model}`; `resolveHost` stays a byte-identical wrapper around `.hostName` for every pre-32.3 caller. `core/router.js`'s `resolveAdapter` surfaces the resolved model alongside the adapter. Verify-first inventory found the routed model reaches every headless host by an identical `--model <value>` CLI flag (`claude`, `codex`, `gemini`, `agy`) — `core/adapters/headless.js`'s shared `runHeadless` appends it generically when `descriptor.model` is set, so claude-code/codex/gemini-cli/antigravity needed no adapter-specific code. `hosts/openai-compat/invoke.js` and `hosts/omnigent/adapter.js` (both non-`runHeadless` paths) were extended so the routing-pinned model takes precedence over their existing `hosts.openai-compat.models`/`hosts.omnigent.model` config, preserving that config as the fallback. The model actually requested is stamped onto the dispatch's gate as `model_requested` (orchestrator-set, fire-and-forget, mirroring the `_orchestrator_observed`/`_orchestrator_stamped` provenance pattern — distinct from the model-asserted `model` field and from `_orchestrator_observed.model_observed`) and threaded into `.devteam/corpus/dispatches.jsonl`. New `routing.tiers` (per-host ordered cheap→frontier model ladder) + `routing.escalate_on_retry` (default `false`) bump a pinned model exactly one tier on a fix-and-retry re-dispatch (`core/config.js`'s `escalateModel`, applied in `core/orchestrator.js` when the driver signals `opts.isRetry`), recorded as `_orchestrator_escalated: {from_model, to_model, reason, at}`. The "frontier plans, cheap executes" preset is documented as an opt-in config block in `docs/user-guide.md` + `docs/cost.md` — not a changed default. `scripts/performance.js` gains an additive `aggregatePerformanceByModel` (groups `(role, host, model)` instead of `(role, host)`, leaving the existing aggregation untouched) feeding a new "per-tier cost delta" section in `npm run routing:suggest`'s report.
  - Tests: `tests/config.test.js` (`resolveRoute` back-compat + object-form + critic-diversity-with-object-routes + `escalateModel`), `tests/router.test.js` (`resolveAdapter` surfaces `model`), `tests/headless.test.js` (`--model` reaches the spawned command; absent when unpinned), `tests/openai-compat-adapter.test.js` and `tests/omnigent-adapter.test.js` (routing pin overrides host-native config; falls back when unset), `tests/orchestrator.test.js` (`model_requested` stamped on the gate; escalate-on-retry bumps/doesn't bump per config; three fire-and-forget cases for the new patch function), `tests/run.test.js` (driver passes `isRetry: true` only on a fix-and-retry re-dispatch), `tests/corpus.test.js` (`model_requested` round-trips into the corpus record), `tests/performance.test.js` and `tests/routing-suggest.test.js` (`aggregatePerformanceByModel` / `buildTierDeltas` / `renderTierDeltas`).
  - Honest scope note: escalation is a single one-tier bump per fix-and-retry dispatch, not cumulative across repeated retries of the same stage — a second retry re-escalates from the route's pinned model, not from wherever the first retry landed. Escalation isn't yet folded into pre-dispatch `--budget-usd` enforcement (same gap as D7/28.4's cost-preference work). Fanout entries (`routing.review_fanout`) don't carry a routing-resolved model in this pass — only the primary stage/role resolution path does.
