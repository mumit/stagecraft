### Added

- **GEPA-style offline prompt optimizer — Phase 33.4.** `scripts/prompt-optimize.js` (out-of-band, like `scripts/budget.js` — deliberately not a `devteam` command): given a `--target roles/<role>.md` or `rules/<name>.md` and a mandatory `--budget-usd`, samples the captured eval cases (`.devteam/evals/cases/`, phase-33.1) that exercise the target's stages, runs a bounded (default 4) reflective loop — one frontier-model diagnosis call per iteration proposing a revised file body — and scores each candidate against a real, unmodified `core/evals/run.js` structural baseline, `scripts/prompt-budget.js`'s byte-ceiling accounting recomputed with the candidate's size, and a budget-capped real-model dispatch subset (the candidate patched into a scratch project, never the real repo file). Candidates are kept as a Pareto frontier (pass-rate vs. token size, `arXiv:2507.19457` §3.2) rather than a single greedy winner. Output: a unified diff for exactly the target file (generated by diffing original vs. winning-candidate content directly — never a model-produced diff) plus an evidence table, printed to stdout and written under `.devteam/evals/optimize/`. **Never writes the target file itself** — the diff is for human review like any PR. A candidate whose structured response proposes a different `target_path` than requested is rejected outright (the diff-scope guard).

  Tests: `tests/prompt-optimize.test.js` — end-to-end against the checked-in fixture corpus with a scripted headless host produces a diff touching only the target file plus an evidence table; refuses to run without (or with a non-positive) `--budget-usd`, before any dispatch; a candidate proposing a different `target_path` is rejected with no diff produced; the diagnosis model is invoked exactly `--iterations` times, never more; Pareto-frontier dominance pruning.

  Honest scope note: every host adapter renders a role brief or rule file as a path pointer, never inlined content — confirmed by reading `core/adapters/markdown-host.js` and `hosts/claude-code/adapter.js` (a VERIFY-FIRST check against this item's own claim). A candidate's content therefore never changes the rendered dispatch prompt text, only what a real host CLI reads from disk when it acts on the pointer. "Structurally valid" is checked via the real `core/evals/run.js` stub path (content-invariant, a sanity floor); "within prompt budget" is checked via `scripts/prompt-budget.js`'s own byte accounting with the candidate's size substituted in (this DOES vary per candidate). Locating a role brief's installed copy inside a scratch project for the real-model subset is done generically, by byte-matching installed `.md` files against the original content — untested against any host beyond `claude-code` (verbatim rule-file installs are uniform across every host and don't need this). `--model` selects a dispatch HOST adapter (the `evals run --headless-host` convention), not a raw model id — Stagecraft always resolves an actual model indirectly via host + `routing.tiers`, so this follows that precedent rather than inventing a new flag. Cost tracking reuses `core/evals/run.js#costPreview`'s posture exactly: an input-token estimate priced off the most recently observed model for `(role, host)` in the run corpus — an estimate, never a bill, and `null` (untracked) when no prior dispatch exists to price against, same as a brand-new project's first `evals run --headless-host` sweep.
