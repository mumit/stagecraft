### Added

- **`devteam evals run` — the eval flywheel replay harness (Phase 33.2).** Replays cases captured by `core/evals/capture.js` (33.1) against the CURRENT framework — today's `core/pipeline/stages.js` stage definitions, role briefs, rules, templates, and `render-helpers.js` prompt layout — to catch framework regressions independent of the model. `devteam evals run [--stub | --headless-host <h>] [--filter <stage|id>] [--budget-usd <n>] [--json]`.

  For each matching case, `core/evals/run.js` rebuilds the descriptor via `core/orchestrator.js#buildDescriptor` against today's stage definitions (never the descriptor at capture time — that's the whole point), materializes a scratch project that overlays the case's captured `inputs/manifest.json` blobs onto the target project's own currently-installed `.devteam/` framework files (or this package's bundled defaults, for a target with no live install — e.g. this repo's own fixture corpus), and renders through the same adapter the case recorded.

  `--stub` (default, free, no model): scores the re-rendered prompt structurally — the always-present scaffold sections (`## Objective`, `## Read first`, `## Allowed writes`, `## Gate to write`, the framework preamble when the stage's `readFirst` starts with `FRAMEWORK_READ_FIRST`) are still there, the rendered bytes are within the stage's committed dispatch-budget ceiling (`docs/reference/prompt-budget.md`'s `parseCommittedBudget`), and how far the prompt hash has drifted from the case's recorded one (always reported, never gated — the replay context legitimately differs from the original run's).

  `--headless-host <h>` dispatches for real via the existing `core/adapters/headless.js#runHeadless` machinery (`DEVTEAM_HEADLESS_COMMAND` respected, same as every other headless path). A case whose original failure was later RESOLVED (`resolution.json` present) must come back PASS/WARN now — still FAIL/ESCALATE is a regression and exits 1. An unresolved case has no known-good target status, so its current gate is reported but never fails the sweep. Prints a 29.3-style cost preview (`core/ceremony-preview.js`'s `mostRecentModelObserved`/`pricingFor`, byte-sampled from the actual re-rendered prompts) before any dispatch and refuses to run without `--budget-usd`.

  Output: a human table by default, or JSONL (one line per case + a trailing summary line) with `--json`, for CI consumption. New CI job (`.github/workflows/test.yml`) runs `--stub` over a small checked-in fixture corpus (`tests/fixtures/evals/`) on every push/PR — this repo's own framework regression gate.

  Tests: `tests/evals-run.test.js` — stub scoring on the fixture corpus (all-OK, exit 0); `--filter` by stage id; a case whose stage no longer exists in `stages.js` scores `error` (exit 1); `--headless-host` without `--budget-usd` refuses with a printed cost preview (exit 1); a resolved case redispatched to PASS via a scripted `DEVTEAM_HEADLESS_COMMAND` scores `pass`; the same case scripted back to FAIL (a seeded re-break) scores `regression` (exit 1); an unresolved case still failing scores `still-failing` without failing the sweep.

  Honest scope note: a merge-level case (multi-role stage, `role: null` — see 33.1's capture split between `core/orchestrator.js` and `core/driver.js`) replays against the stage's first currently-configured role only; the case format doesn't identify which per-role workstream actually owned the failure, and this item doesn't add per-role fanout for that class. The committed dispatch-budget ceiling used for the `--stub` budget check (`docs/reference/prompt-budget.md`) includes the role-brief's own bytes, but adapters built on `render-helpers.js` reference the role brief by path rather than inlining it — so the check is a loose sanity ceiling against accidental scaffold bloat (e.g. a runaway learned-context section), not a tight budget for the rendered text itself. `prompt_pack_version` comparison (33.3) and GEPA-style offline optimization (33.4) are separate, not-yet-implemented plan items.
