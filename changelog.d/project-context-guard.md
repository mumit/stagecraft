### Fixed

- **Read-only reporting commands no longer invent a pipeline outside a Stagecraft project (phase-37 item 37.3, `plans/phase-37-interface-and-token-efficiency.md`).** `devteam next`/`summary`/`status`/`log`/`validate` had no initialisation check, so running any of them in a directory that was never `devteam init`-ed silently fell through to `core/config.js`'s defaults and reported a fabricated stage-01 zero-state (`▶️ run-stage — requirements (stage-01)`) as though a real pipeline were waiting there. Added one shared guard, `core/cli/project-guard.js#requireProjectContext`, wired into exactly those five commands: it detects a missing `.devteam/config.yml`, exits non-zero, and prints what's missing plus the fix (`devteam init --host <name>`); `--json` callers get a structured `{error, command, cwd, message, fix}` object instead of a silent zero-state. Commands that legitimately run without a project (`init`, `review`, `review-pr`, `hosts`, `stages`, `help`, `doctor`) are explicitly exempted and asserted so by a meta-test in `tests/project-guard.test.js`, which also checks that the guarded list is actually wired and the unguarded list isn't accidentally guarded — the split can't drift silently as commands are added.

  Honest scope note: the plan's verify-first claim pointed at `core/cli/commands/review-pr.js` as the precedent for this refusal shape, but `review-pr.js` doesn't refuse at all — it silently falls back to a review workspace when `.devteam/config.yml` is absent (phase-36 item 36.5), which is correct behavior for that command, not a refusal. The actual existing refusal-shape precedent is `core/cli/commands/stage.js`'s warn-before-printing check; this fix reuses its wording (adapted from a warn-and-continue into an exit(1) refusal, since these five commands have nothing honest left to report without a project).
