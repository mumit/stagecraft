### Added

- **Docs: external review guide — phase-36 item 36.6 (`plans/phase-36-external-review-mode.md`).** New `docs/external-review.md` documents `devteam review <path>` and `devteam review-pr <number|url>` (36.4/36.5): the two entry points, a per-host enforcement table naming the exact file that backs (or fails to back) each host's read-only claim, the review workspace layout (`core/review-workspace.js`), where a review's evidence lands, and the honest limits — the `acp` `execute` allowlist (`hosts/acp/permissions.js#findReviewExecViolation`) and that `read`-kind calls carry no location check today. Cross-linked from a new `docs/compliance.md` § Reviewing code you don't own; `README.md`'s `--host acp` paragraph now names it as the recommended host for reviewing code you don't own; added to `docs/README.md`'s index.

  Writing the enforcement table surfaced (and now documents) a real gap: in review mode, the non-`acp` post-hoc write-audit (`core/adapters/headless.js`'s `snapshotWritables(ctx.cwd)`) snapshots the review *workspace*, never `ctx.processCwd` (the subject) — it cannot see a subject write at all, and typically no-ops outright since the workspace isn't a git repository. That is weaker than `checkHostHonesty`'s own warning text ("post-hoc audit of what the agent actually wrote") implies for any `--host` other than `acp`.

  Honest scope note: no code changed. The write-audit gap above is documented, not fixed — fixing it (e.g. pointing the audit at `codeRoot` when `ctx.externalReviewMode` is set) is out of scope for a docs item and is left as a follow-up.
