### Fixed

- **Review-mode write targets now resolve into the workspace, not the subject (follow-up to phase-36 item 36.4, `plans/phase-36-external-review-mode.md`).** `core/adapters/render-helpers.js#appendGateFooter`'s `Write to pipeline/gates/<id>.json` line and `core/adapters/markdown-host.js`'s `Produce <artifact>` line were still *relative* paths even under the two-root split (36.1). A real ACP agent resolves a relative path against its own session cwd, which review mode sets to the subject (`ctx.processCwd`), not the workspace — so a real (non-scripted) agent following the prompt literally would either get the write denied (36.1's `codeRoot` check; safe but broken) or would need to infer the workspace's absolute path from context the prompt never gave it. Both now resolve through `resolveFrameworkPath()`, the same helper 36.2 already used for `readFirst` framework entries — byte-identical to today when `ctx.processCwd` is unset or equals `ctx.cwd` (every non-review run), absolute-into-`ctx.cwd` only when they differ. A literal `<name>` placeholder token (peer-review's `pipeline/code-review/by-<reviewer>.md`) survives the resolution unresolved, exactly as before. Four new tests in `tests/external-framework-paths.test.js` (verified to fail without the fix) cover: the gate path, the artifact path, placeholder survival, and the equal-roots byte-identical regression.

- **ACP peer-review dispatches now derive their gate from the review file, matching every other `hooks: false` host.** `hosts/acp/adapter.js` declares `clientCapabilities.fs = {readTextFile:false, writeTextFile:false}` at `initialize` — it has no claude-code-style PostToolUse hook, and until now never called `core/hooks/approval-derivation.js#deriveForProject` the way `core/adapters/headless.js` already does for codex/openai-compat. A real ACP-routed peer-review dispatch therefore had no automatic path from a `pipeline/code-review/by-<role>.md` review file to a derived `stage-05.<role>.json` workstream gate — stage-05's own gate schema documents that gate as "written by the approval-derivation hook only, never authored by an agent," a contract ACP silently didn't honor. Fixed by adding the identical `by-*.md` scan + `deriveForProject` call to `hosts/acp/adapter.js`'s dispatch-close handler, gated on `!timedOut`, idempotent — verbatim mirror of `headless.js`'s block. `tests/review-command.test.js`'s end-to-end test now exercises this directly: `tests/fixtures/acp-stub-review-agent.js` writes cross-review content into each role's `by-<role>.md` (backend reviews frontend/platform/qa, etc.) instead of hand-writing `stage-05.<role>.json`, and relies on the real derivation path to produce it.

  Honest scope note: wiring the second fix surfaced (and required respecting) a third pre-existing behavior — `deriveForProject`'s self-review guard (a reviewer's own area verdict in their own `by-<role>.md` is skipped, never derived, per `.devteam/rules/pipeline.md` §Stage 5). The test stub originally had each role review its own area, which silently produced zero approvals per area with real derivation on; fixed in the stub, not in `approval-derivation.js`, since the guard itself is correct and pre-existing behavior, not a gap.
