- **Escalation guidance now ignores stale Principal outputs.** `devteam next` no longer treats any prior `PRINCIPAL-RULING:` or `PRINCIPAL-CANNOT-DECIDE:` line in `pipeline/context.md` as proof that the current escalation has been resolved. It checks whether existing Principal outputs match the active escalating gate, lets a newer matching ruling supersede an earlier cannot-decide line, and tells the operator to run `devteam ruling --target-gate ...` before `devteam fix-escalation` when nothing matches.
- **Escalation applicators can now keep documentation-only fixes.** `devteam fix-escalation` now permits README, CHANGELOG, `docs/`, and `changelog.d/` writes when a Principal ruling asks for documentation remediation, and unauthorized applicator writes fail the command instead of being removed while still reporting success.
- **Stage 8 now has a no-config local deploy default.** Projects that omit `deploy.adapter` receive a `local` adapter instead of an escalation: Stage 8 records local/in-place verification, marks `adapter_result.external_deploy: false`, and keeps concrete publish targets opt-in. If Stage 7 records `deploy_requested: false`, the orchestrator now writes the local/no-external-deploy Stage 8 gate and deploy log directly instead of dispatching a deploy agent or escalating for a deployment choice.
