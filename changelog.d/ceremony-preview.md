### Added

- **Per-track ceremony cost preview — phase-29 item 29.3.** `devteam assess` (text + `--json`) and the top of `devteam run` pre-flight output now print a per-track estimate before any dispatch: stage slots, dispatch count (`{min, max}` — `min` excludes stages that are conditional at runtime, e.g. `stage-04b` security-review, `stage-04d` migration-safety), a token range, and a cost range, all under a new `core/ceremony-preview.js`. Two estimate sources, always labelled via `estimate_basis` (house honesty rules — every number is an explicit estimate, never presented as a bill):
  - **`"static"`** (default): tokens come from the same per-dispatch framework-overhead numbers `scripts/prompt-budget.js` generates into `docs/reference/prompt-budget.md` — read via its `computeStageStats()` machine source, not the rendered doc — plus the real on-disk byte size of any `pipeline/*` artifact a stage's `readFirst` would load (the gap `prompt-budget.js` itself deliberately leaves as "project-dependent, unknown at analysis time"). Cost requires a model; since a routed *host* (e.g. `claude-code`) is a CLI adapter, not a model, the actual model is only ever known from orchestrator-observed telemetry. The static path resolves "currently-routed model" per `(role, host)` as the most recent `model_observed` for that pair in `.devteam/corpus/dispatches.jsonl` (28.5) — independent of the empirical run-count threshold below. If *any* dispatch's model can't be resolved this way, the whole track's `cost_usd` is `null` (never a partial, misleadingly-precise total) and the unresolved `role@host` pairs are listed in `unresolved_models`.
  - **`"empirical"`**: once the corpus has ≥5 completed runs (`run_id`) of the exact same track, tokens/cost are the median observed totals across those runs instead of the static formula.
  `devteam run`'s pre-flight `run-plan` event now carries `ceremony_preview`, computed against the same right-sized stage list `summarizeRunPlan` already derives (respects `pipeline.skip_stages` and right-sizing skips), so the estimate matches what will actually dispatch; this replaces the `TODO: cost estimate — plans/phase-29-scale-adaptive-ceremony.md 29.3` placeholder line 29.2 shipped. Computing the preview is advisory-only (wrapped in `try/catch` in both `devteam assess` and `core/driver.js`) — a preview failure never blocks a run or an assess recommendation. Tests: `tests/ceremony-preview.test.js` (static estimates for `loop`/`quick` with no corpus history; model resolution from a single sub-threshold corpus record; unknown-model path never invents a partial dollar figure; on-disk artifact sampling widens the token range; empirical-basis median switch at the 5-run threshold and its two negative cases; `devteam assess` `--json`/text surfacing); `tests/run.test.js` updated (the 29.2 "TODO" placeholder assertion now asserts the real `Ceremony estimate (static): ... — (unknown model)` line, since the fixture has no corpus history).
  Honest scope note: the static estimate does not model stage-01 `active_roles` suppression or per-workstream right-sizing beyond the stage-level skips `summarizeRunPlan` already applies — it assumes every track-shape role dispatches, so a run that later suppresses e.g. an inactive `frontend` workstream will come in under the static estimate, never over. `devteam assess` (no run context) always uses the nominal track shape; only the `devteam run` pre-flight path narrows to the right-sized stage list.
