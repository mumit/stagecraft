### Added

- **Run corpus: one sanitized JSONL record per headless dispatch, plus `devteam corpus stats` — Phase 28 item 28.5.** After every headless dispatch (`devteam run`, `devteam stage --headless`, `devteam replay`, the a11y-fixer), the orchestrator appends one line to `.devteam/corpus/dispatches.jsonl` (project-local, gitignored by the managed block, never uploaded): `{ts, run_id, stage, role, host, model_observed, track, prompt_hash, prompt_bytes, tokens_in, tokens_out, cost_usd, cost_basis, duration_ms, queue_ms, gate_status, blockers, retry_of, framework_version}`. Fields missing for a given dispatch are `null`, never omitted. `model_observed`/tokens/`cost_usd` prefer the gate's `_orchestrator_observed` block over model-asserted top-level fields (same trust-boundary pattern as `core/verify/stamp.js`); `cost_basis` records which one won. `blockers` are sanitized through the same secret-scan path (`core/hooks/secret-scan.js scanContent`) `core/patterns.js` collection uses — a blocker containing secret-shaped text is fully redacted before it ever reaches disk. Writes are fire-and-forget: an unwritable `.devteam/corpus/` directory logs one warning and never fails the run. New `devteam corpus stats [--json]` reports total dispatches, per-stage pass rates, and per-(role, host) dispatch counts — worded to answer the D5/H3 evidence-gate questions in `docs/BACKLOG.md` directly. `.devteam/corpus/` added to the managed gitignore block. `scripts/routing-suggest.js` (D5) now reads the corpus as an additional data source alongside `pipeline/gates/` archives, so dispatch history survives gate archiving/pruning. Docs: `docs/observability.md` "Run corpus" section. Tests: `tests/corpus.test.js` (14 new) — one corpus line per dispatch with correct fields via a stubbed multi-stage headless run, a planted secret in a blocker never reaching disk (both the parsed field and the raw file content), `--skip-completed` no-op dispatches excluded, an unwritable corpus directory logging exactly one warning without throwing or failing a real dispatch, `devteam corpus stats` aggregating a fixture corpus (including a malformed line being skipped) via both the module API and the CLI, and `scripts/routing-suggest.js` merging corpus records into `aggregatePerformance`. Honest scope note: the experimental `--experimental-omnigent-director` dispatch path is not yet recorded to the corpus (it predates per-dispatch usage telemetry entirely); cross-project D5/H3 aggregation remains a manual step — the corpus itself is local-only and never combined across projects automatically.
