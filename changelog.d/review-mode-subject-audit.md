### Fixed

- **Non-`acp` hosts' post-hoc write-audit was blind to the subject in review mode — phase-36 item 36.6 follow-up (`plans/phase-36-external-review-mode.md`).** In review mode (`ctx.externalReviewMode`), the existing post-hoc write-audit for `codex`/`antigravity`/`omnigent`/`openai-compat` snapshotted `ctx.cwd` (the review workspace) before and after a dispatch, never `ctx.processCwd` (the subject under review) — so it structurally could not see a write into the subject, and typically no-op'd entirely since the workspace isn't a git repository. `core/adapters/headless.js` and `hosts/omnigent/adapter.js` now run a second, independent snapshot/audit pass against `ctx.processCwd` when review mode is active and the subject differs from the workspace, treating any new path there as a violation unconditionally (`subject:<path>`, mirroring `hosts/acp/permissions.js`'s own rule that `codeRoot` is unconditionally read-only) — flipping the gate to `FAIL` with a named blocker. This is detection, not prevention: it cannot stop the write, only report it after the fact, and it inherits the write-audit's existing blind spots (no-ops on a non-git subject; can't see a re-edit of a file already dirty before the review started). Guarded to never double-audit when `ctx.processCwd === ctx.cwd`, and to stay a no-op for prototype mode (`ctx.processCwd` set without `ctx.externalReviewMode`).

  Five new tests (`tests/write-audit.test.js`, `tests/omnigent-adapter.test.js`) cover: detection when the workspace isn't a git repo but the subject is; no detection without `externalReviewMode` (prototype-mode parity); and no double-audit when `codeRoot === stateRoot`. Confirmed to fail without the fix.

  `docs/external-review.md`'s per-host enforcement table, `README.md`'s `--host acp` note, and this plan's 36.6 entry are updated to describe the new three-tier picture precisely: `acp` prevents, `codex`/`antigravity`/`omnigent`/`openai-compat` now detect, `claude-code` still gets neither (a known, separately-tracked gap — `--state-dir` for claude-code, phase-36's own Out-of-scope list).

  Honest scope note: `claude-code`'s hook-discovery gap in review mode is unchanged by this fix — it is out of scope for this phase by the plan's own design, not an oversight here.
