### Added

- **Failed gates become replayable eval cases — Phase 33.1.** Every stage FAIL/ESCALATE, and every orchestrator stamp `status_overridden` (the model-lied class — always captured, since it's already a FAIL), now writes a case under `.devteam/evals/cases/<ts>-<stage>-<hash>/`: `case.json` (stage/role/host/track, an orchestrator-computed `prompt_hash`, the gate's C4 reproducibility fields via `core/reproducibility.js#reproducibilityFingerprint`, a sanitized gate snapshot, framework/stamper versions) and `inputs/manifest.json` describing the stage's `readFirst` artifact set. Artifact content is content-addressed (sha256) into `.devteam/evals/blobs/`, deduped across cases; a file that scans positive through `core/hooks/secret-scan.js` (the same path the stage-04c mechanical red-team floor uses) is excluded from the blob store entirely — the manifest records the exclusion and which pattern fired, never the content. `core/verify/stamp.js` finding lint/tests actually failing after a model claimed PASS flips the gate as before; the new capture path just observes whatever status lands.

  Single-role stages are captured in `core/orchestrator.js#runStageHeadless` (alongside the existing `core/corpus.js` fire-and-forget dispatch record — same point, so the post-stamp status is what's captured, never the model's pre-stamp claim). Multi-workstream stages (build, peer-review) are captured in `core/driver.js`'s merge branch, after `stampMerged` — that's the only place the stage's true final status (post per-role stamps *and* the merge-time stage-05 approval re-derivation) is known.

  A resolution-linker pass runs at the end of every `devteam run` (fire-and-forget, same slot as pattern auto-collection/reflector/memory-ingest): for each captured case with no `resolution.json` yet, it looks for a `fix-retry` run-log event on the same stage logged after capture, and — if the stage's current on-disk gate is no longer FAIL/ESCALATE — appends `resolution.json` naming which retry cleared it.

  New config: `evals.capture` (default `true`) opts a project out entirely. New command: `devteam evals gc` removes `.devteam/evals/blobs/` entries no case's `inputs/manifest.json` references anymore. `.devteam/evals/` joins the managed `.gitignore` block (local-only, like `.devteam/corpus/` — no cross-project or cross-run aggregation).

  Tests: `tests/evals-capture.test.js` — a stubbed FAIL dispatch (via `runStageHeadless`) produces a complete case directory; a real `stampStage04a` status_overridden is captured with `capture_reason: "stamp-override"`; a multi-workstream merge FAIL is captured via `core/driver.js#run` with an injected `mergeWorkstreamGates`; a fix-retry run-log event followed by the stage's gate turning PASS links a `resolution.json`; two cases sharing identical artifact content dedup to one blob; `evals.capture: false` captures nothing; a planted secret in a readFirst file is excluded from the blob store; `devteam evals gc` removes only unreferenced blobs.

  Honest scope note: capture is local-only and per-project (mirrors `core/corpus.js`'s scope decision) — there is no bounded-isolation (`pipeline/changes/<id>/`) plumbing for `.devteam/evals/`, matching the run corpus's own precedent. The resolution-linker's "which retry cleared it" is a best-effort correlation by stage id and timestamp ordering against `run-log.jsonl`, not a strict causal proof — a stage that flaps FAIL→PASS→FAIL→PASS within one run links every earlier unresolved case to the same final clearing retry. `devteam evals run` (the replay harness) and `prompt_pack_version` (33.2/33.3) are separate, not-yet-implemented plan items — this item only builds the capture substrate they'll consume.
