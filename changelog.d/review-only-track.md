### Added

- **`review-only` track + artifact-tolerant readFirst — phase-35 item 35.1 (`plans/phase-35-existing-codebase-mode.md`).** Reviews code that already exists — a brownfield repo, an inherited module — instead of assuming the intent→code direction every other track takes. `devteam run --track review-only [--scope <path>]` dispatches `security-review` → `red-team` → `peer-review` only: no requirements, design, build, sign-off, or deploy. `--scope <path>` (repeatable) narrows the review to a subtree; it renders as a "Scope: ..." prompt line and lands on the gate (`scope: [...]`) for audit, both only when passed (every other track's prompts/gates are unaffected).

  **Soft readFirst.** `core/pipeline/stages.js`'s pipeline-artifact `readFirst` entries for `security-review`, `red-team`, `peer-review` (including the 31.3 adversarial override), and `verification-beyond-tests` are now `{path, optional: true}` — the same form 31.3/G3 already established for `by-reviewer.md`/`production-feedback.md`, extended rather than duplicated into a parallel array. `core/orchestrator.js#buildDescriptor` now backs `optional: true` with a real filesystem check (`existsForReadFirst`, glob-aware for `pipeline/pr-*.md`) instead of the pre-35 behavior of always rendering the entry annotated `"(if present)"`: an absent optional path is omitted from the `## Read first` section entirely, a present one renders plainly (indistinguishable from a required entry). No `cwd` in scope (a preview/eval-replay path with nothing to check against) fails open — assume present, matching every pre-35 caller. This closes the "review stages instructed to read files that don't exist, degrading instead of failing" gap the phase exists to close.

  `security-review`'s `conditionalOn: {stage: "stage-04a", ...}` already treats a missing prerequisite gate as "run it anyway" (existing `core/orchestrator.js` behavior, not new here) — since `review-only` never dispatches `stage-04a`, security-review runs unconditionally on this track, same as red-team and peer-review.

  Tests: `tests/review-only-track.test.js` — optional-entry omission/inclusion (plain path, glob, no-cwd fallback); full-track byte-identical regression for all four touched stages (rendered prompt identical to a hand-authored plain-string-readFirst copy when every artifact is present); `devteam run --track review-only` walks to `pipeline-complete` on a fixture with **no `pipeline/` directory at all**; no dispatched `## Read first` section mentions a nonexistent artifact; `verify-chain` passes on the 3-stage track; `--scope` reaching the prompt and the gate, and its absence changing nothing on every pre-35 track. `tests/compact-qa-fold.test.js`'s `verification-beyond-tests` snapshot and `tests/tracks.test.js`'s "build is in every track" assertion updated for the new readFirst shape and the one track that legitimately never builds anything.

  Honest scope note: item 2's plan text called for gate-schema conditionals making "AC-referencing fields null-permitted when track: review-only" (the 29.4 stage-06x precedent). **Verify-first check found this premise false**: none of `security-review`/`red-team`/`peer-review`'s gate schemas (`core/gates/schemas/stage-04b|04c|05.schema.json`) have any required field that references acceptance criteria — the AC↔Scenario↔test contract lives entirely in stage-01/03b, neither of which this track includes. No schema conditional was added; there is nothing to relax. `core/gates/schemas/gate.schema.json`'s `track` enum gained `"review-only"` (it was already missing `"loop"` — pre-existing drift, not fixed here, out of scope). Peer-review sizing on `review-only` falls through to `PEER_REVIEW_SIZING.full` (the 4-area matrix, 2 approvals) rather than a scoped single-reviewer variant — unlike `nano`/`loop` there's no single-workstream build to size the review to, and an arbitrary existing subtree can span every area.
