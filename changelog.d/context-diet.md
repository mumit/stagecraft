### Added

- **`pipeline/context.md` diet: byte budget + auto-compaction, and a per-workstream context-changes delta — phase-32 item 32.5 (`plans/phase-32-performance-parallelism.md`).** Verify-first confirmed `context.md` grows via `devteam:*` marker sections written by `core/gates/validator.js` (red-team-blockers, qa-build-blockers) and `core/driver.js` (run-blockers, right-sizing, deploy-target), that `devteam compact` unconditionally strips every marker section (unchanged by this item), that every dispatched stage's `readFirst` only ever points at the whole file (never inlines it), and — new finding — that no event previously recorded a marker section write/strip, so that was added first as its own commit. New `core/context-log.js` (`logContextSectionEvent`, fire-and-forget) records every marker add/remove to `run-log.jsonl` as a `context-section-change` event. New `pipeline.context_budget_bytes` config (default `8192`) is enforced by new `core/context-budget.js` right after every marker write: over budget, the oldest RESOLVED marker section (in document order; a section is "resolved" only when this module has a rule mapping it to a stage gate whose status is PASS/WARN — currently `right-sizing`→stage-01, `deploy-target`→stage-08, `red-team-blockers`→stage-04c, `qa-build-blockers`→stage-04.qa) is replaced with a one-line digest pointing at its full text, archived append-only under `pipeline/context-archive/<ts>-<section>.md`. New `core/context-delta.js` (`computeContextDelta`) derives, purely from `run-log.jsonl` history, which sections changed since a workstream's *own* previous dispatch (correct across retries — only counts events after that workstream's most recent prior `workstream-started` event); `core/orchestrator.js`'s `plan()` computes it per workstream and threads it onto the descriptor, and a new `renderContextDelta` (`core/adapters/render-helpers.js`) renders a "## Context changes since your last dispatch" section in every host adapter's volatile-tail layer (`core/adapters/markdown-host.js`, `hosts/claude-code/adapter.js`, `hosts/generic/adapter.js`) — omitted on a workstream's first-ever dispatch or when nothing changed. `core/markers.js` gained `parseSections` (promoted out of `core/cli/commands/compact.js`, which now imports it) so both the manual compactor and the new budget auto-compactor walk the same section-parsing logic.
  - Tests: `tests/context-log.test.js` (event shape, fire-and-forget, changeId-scoping, validator/driver call sites), `tests/context-budget.test.js` (under-budget no-op, resolved-section compaction + archive round-trip, unresolved/no-rule sections survive arbitrarily over budget, multi-section compaction order, idempotent re-run, missing-file no-op), `tests/context-delta.test.js` (first-dispatch null, cross-workstream isolation, retry-sequence correctness, changeId scoping, malformed-line tolerance), `tests/render-helpers.test.js` and `tests/orchestrator.test.js` (delta section rendered/omitted end-to-end through `runStage`), `tests/config.test.js` (`context_budget_bytes` default/override/invalid-value fallback).
  - Honest scope note: event logging and budget enforcement are wired only into the writers the verify-first claim named (validator.js, driver.js) — `core/advise.js`'s `devteam:advise` section and `core/cli/commands/restart.js`'s generic strip are not instrumented, so advise-authored growth isn't tracked or auto-compacted (still fully covered by manual `devteam compact`). "Resolved" detection is a static 4-section allowlist keyed to a single gate file each; any other marker section (present or future) is always treated as active and never auto-compacted, so budget pressure from those never self-relieves. "Oldest" is document order, not a true write timestamp (none is recorded per-section), so it's an approximation for sections written via `insert: "prepend"`. `pipeline/context-archive/` was not added to ADR-010's canonical `.gitignore` block (`core/gitignore.js`) — out of scope for this item since it means editing an accepted ADR; a follow-up should add `pipeline/context-archive/` and `pipeline/changes/*/context-archive/` alongside the existing `pipeline/gates/archive/` entry.
