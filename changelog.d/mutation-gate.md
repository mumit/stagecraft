### Added

- **Opt-in mutation smoke gate for stage-06 — Phase 31.4.** `core/verify/mutation.js`, wired into `core/verify/stamp.js#stampStage06`. Disabled by default (`pipeline.verify.mutation.enabled: false`); when enabled, the orchestrator detects a supported mutation-testing runner already present in the target project — Stryker via a `@stryker-mutator/core` package.json devDependency (JS/TS), mutmut via the binary already on PATH/venv (Python), never installed by devteam — and runs it against the changed-file set only (`pipeline/changed-files.txt`, the same source `redteam-floor.js` uses), intersected with an optional `pipeline.verify.mutation.paths` scope. The run is time-boxed via `pipeline.verify.mutation.timeout_ms` (default 5 min), reusing `runCommand`'s existing `core/process-kill.js` machinery — a hung run is killed and recorded as a skip, never a false pass. The parsed score, runner, and scope are stamped onto the gate as `mutation_score` / `mutation_runner` / `mutation_scope`. Below `pipeline.verify.mutation.threshold` (default `0.7`) is advisory: a gate warning plus a `noted_for_followup` entry (`severity: "high"`) so it surfaces in `devteam advise` classification (routes to `PEER_REVIEW_RISK`) rather than being silently absorbed; it only becomes a blocking FAIL when `pipeline.verify.mutation.threshold_hard: true`. An absent runner, an empty scope, a timeout, or unparseable tool output are all recorded as an honest skip. `docs/verification-beyond-tests.md` now documents this mechanical gate distinctly from stage-06d's model-driven, full-track-only mutation pass, which it does not replace.

  Tests: `tests/verify-stamp-mutation.test.js` — disabled-by-default leaves stage-06 untouched; no-runner and empty-scope cases record honest skips; a below-threshold fixture WARNs and its `noted_for_followup` item classifies `PEER_REVIEW_RISK` via `core/advise.js#classifyItem`; an at/above-threshold score does not warn; `threshold_hard: true` flips a model-PASS gate to FAIL; a hung mutation command is killed cleanly at `timeout_ms` and recorded as a skip; unit coverage for runner detection, path-scope intersection, and Stryker output parsing.

  Honest scope note: mutation-tool output parsing is regex-based against each tool's documented clear-text summary format (Stryker's `N/M mutants killed (X%)` line, per `skills/verification-beyond-tests/SKILL.md`'s worked example; mutmut's emoji progress line) rather than a structured report file — unparseable output is always an honest skip, never a fabricated score, but a future tool version that changes its summary format will silently downgrade to skips until the regex is updated. `pipeline.verify.mutation.command` is an added override beyond the plan item's literal config shape (`{enabled, threshold, threshold_hard, timeout_ms, paths}`), mirroring the existing `dependency_audit_command` override from 31.2 — without it there is no way to exercise the run/parse/threshold pipeline in tests without a real Stryker/mutmut install, which devteam must never do. mutmut's real-world output format is inferred from documented CLI behavior, not verified against a live install; the Stryker-format branch is exercised end-to-end via the same override, but neither runner's auto-detection path (real `npx`/`mutmut` invocation) is exercised in CI, the same limitation `runSemgrepFloor`'s tests already accept for a binary devteam cannot assume is installed.
