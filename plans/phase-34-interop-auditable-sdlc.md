# Phase 34 — Interop & the Auditable SDLC

Status: **proposed** (from [landscape-review-2026-07.md](landscape-review-2026-07.md) §3.7, §4).
Prompts: [prompts/roadmap-2026-prompts.md](prompts/roadmap-2026-prompts.md) §34.

## Why

Two market facts. First, ACP (Agent Client Protocol — Zed, JetBrains, Google, GitHub,
25+ agents) standardizes exactly the boundary `hosts/*/adapter.js` hand-maintains; one
ACP adapter turns "6 first-party adapters + a maintenance treadmill" (the A2 objection)
into "any ACP agent is a host." Second, the compliance space is unowned: no competitor
ships signed, machine-readable stage-gate evidence; provenance standards exist below
(SLSA v1.2, in-toto, Sigstore) but nothing claims the SDLC-decision layer, and EU CRA
milestones (Sept 2026) are pulling enterprises toward exactly what the gate chain
already records. Stagecraft's heaviest ceremony becomes its best product when the output
is regulator-shaped evidence.

## Work items

### 34.1 ACP host adapter

`hosts/acp/` speaking Agent Client Protocol as a client: dispatch = open session,
deliver the rendered stage prompt, stream progress into `pipeline/logs/`, apply ACP
permission semantics (map stoplist/allowed-writes to ACP permission requests —
tool-call-time enforcement on every ACP host, closing part of the enforcement-parity
gap that today only claude-code has), collect the gate file as usual. Config:
`routing.roles.<role>: acp:<agent-command>`. Capabilities declared honestly per
negotiated ACP features. Contract tests via a scripted ACP stub agent (no network).

- Acceptance: adapter passes `tests/adapter-contract.test.js` structural checks; a
  scripted ACP session completes a stage end-to-end in tests; permission mapping
  blocks a stoplisted write at call time in the stub.
- Verify: `npm test`, `CI=true DEVTEAM_HEADLESS_COMMAND=cat npm test`, `npx eslint .`,
  `npm run consistency`.

### 34.2 Attestation export: gate chain → in-toto/SLSA-shaped bundle

`devteam evidence export --attestation [--sign]`: transform the verified gate chain
(ADR-011 HMACs and all) plus run metadata into an in-toto-statement-shaped JSON bundle —
subject = the commit(s) produced, predicate = per-stage gate evidence (status, who/what
verified it, orchestrator-observed vs model-asserted provenance per field, prompt-pack
version, model versions from C4 reproducibility fields). `--sign` shells out to
`cosign sign-blob` when present (never bundled). Verification counterpart:
`devteam evidence verify-attestation <bundle>` re-checks internal hashes offline. Builds
on the Phase 16/17/18 evidence subsystem (identity, privacy bounds, resolutions) — this
is its productization.

- Acceptance: bundle validates against a checked-in JSON schema; round-trip
  verify passes; tampered bundle fails; hash-bound human resolutions (ADR-012) appear
  as their own predicate entries.

### 34.3 Control mapping + audited-track documentation

`docs/compliance.md`: a table mapping pipeline artifacts to control families — change
approval (stage-07 sign-off + ADR-012 acceptance records), segregation of duties
(per-role dispatch provenance, reviewer ≠ author hosts), testing evidence (stamped
04a/06 + receipts), security review (04c mechanical floor from 31.2), deployment
control (consequence ceiling + `--allow-stage` grants), tamper evidence (verify-chain).
Explicitly scoped as "evidence your auditors can map," not "certified compliance" —
house honesty rules. Cross-link from README's audited-path positioning (29.5).

- Acceptance: `npm run consistency` doc checks pass; every claim in the table names the
  artifact file and the command that verifies it.

### 34.4 Retire/park the gemini-cli adapter (completes 28.6)

After one deprecation release with the doctor warning live: move `hosts/gemini-cli/` to
plugin-package status (`@devteam/host-gemini-cli`) per the A4 mechanism, update docs and
init host lists, keep contract tests in the plugin. First-party surface becomes:
claude-code, codex, antigravity, openai-compat, acp, omnigent, generic.

- Acceptance: `devteam init --host gemini-cli` still works via the plugin path with a
  clear notice; consistency host-list checks updated.

## Out of scope

Hosting/uploading evidence bundles (local + export only; no service), SOC 2
certification claims of any kind, ACP *server* mode (Stagecraft as an agent other tools
drive — interesting, separate ADR), signing-key management (cosign/KMS is the user's).

## Success signal

A regulated-team pilot can hand an auditor a signed bundle proving who/what
built-reviewed-tested-approved a change, generated by `devteam evidence export` — and a
new agent CLI works as a Stagecraft host the day it ships ACP support, with zero
adapter code written here.
